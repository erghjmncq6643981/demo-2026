## 运维修复接口与权限

运行端接口与管理端 REST 是独立适配器。不能直接把以下接口拼进 `/api/admin`，也不能把原始载荷暴露给普通坐席。

- `GET /api/telephony/recovery/events?page=1`：固定每页 50 条脱敏摘要。
- `POST /api/telephony/recovery/events/{eventId}/reconcile`：只允许重读持久源 DESTROY，校验事件摘要、话道、节点和源时间，再精确解析已有 Call/Leg。不自动创建未知关联，不重放 originate/bridge。
- Controller 与应用服务均在线核验 CONSOLE 身份，需 `telephony:recover` 或超级管理员 `*`。`cdr:view`、普通坐席令牌均不能修复。
- `RECOVERING` 五分钟后可重新领取；新 token 防止旧执行者覆盖结果。动作先写入 `fcc_event_recovery_action`，记录操作者与结果。`RECONCILED` 只表示结束事实已对账，不表示整个流程或录音成功。
- 操作中断留下的 RUNNING 审计不伪造完成；重新领取产生新动作。达到十次上限后拒绝自动领取，必须先人工排查，不能把计数清零当成问题解决。
- 已完成事实但审计完成更新失败时保留 RECONCILED，返回明确错误，不把已修复事件退回 UNKNOWN。需要人工核对动作审计。

## 监控口径与查询形状

`GET /api/admin/monitoring?period=day|week|month&date=YYYY-MM-DD` 要求 `cdr:view`。业务时区为 Asia/Shanghai，周一为周起点，数据库查询 UTC 半开区间 `[start,end)`，最长一个月。返回紧凑统计桶，不返回通话身份、号码、录音或原始事件。

接通依据 answered_at、正通话时长、明确 ANSWERED/COMPLETED 或 ANSWER 结果；NORMAL_END 本身不作为接通证据。自动外呼通过 dial-attempt 与 AUTO_FLOW job 的 EXISTS 判定，避免一通多尝试 JOIN 放大计数；“智能外呼”是呼出子集，各分类卡片不可简单相加求总量。总趋势直接对唯一统计桶求和。

新增 `fcc_call_session(started_at)` 范围索引：时间前导覆盖单周期扫描，高基数时间降低候选范围；每次新增/改变开始时间增加一份索引写入。自动任务关系沿用 dial-attempt(call_id) 和 job 主键，未另加复合索引。复杂度仍与选定周期事实数相关，不声称恒定耗时；上线前对真实分布 EXPLAIN ANALYZE。

## 数据库升级顺序与修复策略

全新安装用 `fcc-schema.sql`；存量数据库不能重跑基线升级。以下脚本尚未执行，只有静态审查和 Mapper 解析证据。

1. 在专用 MySQL 8 验证库验证 [运行可靠性升级脚本](upgrades/2026-10-04-runtime-reliability.sql)。核对已有列和索引、备份受影响表，确认脚本没有执行过；该 ALTER 脚本不能重复执行。
2. 检查 service-session 的非空 leg_id 重复、leg_id 指向不存在 Leg、Call/Leg 归属不一致。发现异常先保留记录并人工确认，不自动删历史。非空 leg_id 唯一键只在检查通过后添加；现有 leg_id 普通索引暂保留，存在冗余写成本，后续须验证查询计划后单独升级移除。
3. 安排维护窗口暂停 FCC 写入/消费，确认 JetStream 保留窗口足够；执行新增列、索引与表的 DDL，然后部署后端，再部署依赖新监控接口的管理前端。没有新增 Sidecar 方法或字段，无需假定双方同时部署。
4. 新字段默认值支持已有事实；重试次数从零开始，旧 UNKNOWN 可通过新入口受控处理。不自动把旧 PROCESSING、UNKNOWN 或运行中通话标成成功。
5. 当前迁移**不回填历史参与**。已存在参与保留，后续普通 Leg 写入同步；只同步结束不能创建缺失参与。历史/当前存量缺口需后续应用侧按明确 agentWorkNo 分页，生成独立 Snowflake 参与 ID，在 Call 锁内调用幂等同步；未知工号或归属冲突列入报告，不猜测工号、不用 Leg ID 冒充参与 ID。
6. 核对消费者恢复、普通话道参与、重复 DESTROY、转接重启及统计查询，再恢复流量。独立的通知目录 V2 升级仍按 [通知模型升级说明](upgrades/NOTIFICATION-MODEL.md) 执行，与本脚本无数据依赖。

MySQL DDL 会隐式提交，不能依赖事务回滚。失败时停止部署，逐项核对已执行 DDL，只修复尚未完成步骤。兼容窗口内可以回退应用并保留新增表/列和审计，不 DROP 事实表、不删除审计、不自动重拨。前端回退需与统计 API 兼容；旧应用不会识别新增恢复状态，回退前必须停止人工修复并检查未完成动作。
