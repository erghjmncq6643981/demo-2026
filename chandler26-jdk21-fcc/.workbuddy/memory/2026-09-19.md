排查过程中修掉的两处（都是真实缺陷，非为凑测试）：

1. **残留服务抢消费事件导致的假失败** —— 先停掉残留的 fcc-server(8085)/fcc-admin(8089) 后复现消失，证实为环境干扰。
2. **`CallPersistenceService.saveOrUpdateSession` 终态被错误归一化** —— 原实现在会话终结时把 `status` 覆盖成 `ANSWERED/NO_ANSWER`、`result` 覆盖成 `ANSWER/MISSED`，导致事实表丢失 `NORMAL_END/ERROR_END` 终态、事后无法区分正常结束与异常结束（违背 AGENTS.md「状态显式且单调」）。已改为：终态如实保留生命周期状态，`result` 保留挂机结果码（FreeSWITCH cause），话单层「已接听/未接听」由查询侧依据 `answeredAt` + 通话时长推导，不回写事实表。
3. **CDR 的 `audioDuration` 与 `recordingUrl` 语义混淆** —— 我一度把「无录音则 audioDuration 置空」当作修复，但这会让"显示时长"这个中性字段承担"能否复播"的语义。正确做法是：`audioDuration` 只表达时长（优先取录音事实时长，回落通话时长）；是否能复播由 `recordingUrl` 是否为空表达。前端 `CdrReportView` 的试听入口相应改为 `v-if="item.recordingUrl"`，仅有通话时长而无录音文件时只展示时长文本。

## 第三轮改造：录音落到 ~/fcc-records + 删除话务仿真 + 弹屏改为全真实（已实测通过）

用户决策：①录音共享目录用 `~/fcc-records`；②`TelephonyWsSimulationController` 这类模拟接口与代码全部去除；③来电弹屏可以简化，但**必须是真实的**。

### 关键设计决定：弹屏的"真实性"边界

系统内**没有 CRM 表**，所以原先那套「客户 360 画像」（客户等级 / 在租箱数 / 年保费 / 待办工单 / 推荐话术 / `media.boxbox.com` 录音地址）**没有任何事实来源**，全部是编造值。处理原则定为：**取不到真实值一律留空**，绝不用示例数据填充，前端对空值展示中性占位。`IncomingScreenPopDTO` 因此从 24 个字段精简到 **14 个**，每个字段都能对应到明确的事实来源：

| 字段 | 真实来源 |
| --- | --- |
| `callId` / `direction` / `callerNumber` / `didNumber` | 通话上下文（NATS 通道事件驱动），呼入取主叫+被叫，呼出取反向 |
| `ringTimeoutSeconds` | 实际下发 `FNode.Dial` 的 timeout（常量 30，与振铃倒计时同源） |
| `flowName` | `fcc_flow_definition.flow_name`（由 `FlowConfig` 编译已发布流程时登记的反查表） |
| `ivrPath` / `routingReason` | 真实捕获的 `ivrSelectedDigit` + 流程名 + 真实目标坐席/终端 |
| `customerName` / `companyName` | **仅**坐席外呼时在工单里录入的值 |
| `lastAgentName` / `lastAgentWorkNo` / `lastCallTime` / `lastCallSummary` | `fcc_call_session` 中同号码最近一条**已结束**通话 |
| `lastRecordingUrl` | `fcc_call_recording` 存在录音元数据时才给出，指向 `/api/admin/recordings/{callId}/stream` |
