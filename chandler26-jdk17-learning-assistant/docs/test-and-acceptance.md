# 测试与验收

## 自动检查

后端：

```bash
mvn -q -DskipTests compile
mvn -q test
```

前端：

```bash
npm run check
npm run lint
npm test
npm run build
npm run e2e
```

数据库或供应商不可用时，应明确记录未验证项，不能以 Mock 或单元测试代替真实端到端结论。

## 核心业务验收

- 公共词表：导入、断词修正、发布、全局语义复用和失败项重试。
- 学习计划：创建计划、日历摘要、场景生成、详情按需加载和材料历史保留。
- 词汇挑战：含义选择、拼写检查、逐词记录和复习安排。
- 知识反刍：单一预置参考场景与 AI 动态宇宙开辟、用户词本语义关联度全量筛选（不做数量上限）、2D 暗夜星系多环同心行星轨道渲染、纯净几何连线与 Authentic 4D 衍生展开、Cmd+滚轮独立缩放、非侵入式原地词袋 Toggle、场景材料编织后词袋自动清空（每篇材料固化专属原料词）、微场景材料与微环境探针并列按需展开、即时反馈与星系节点脉冲点亮，以及全链路三大独立持久化表与词本复习结算落库（`learning_rumination_graph`、`learning_rumination_material`、`learning_rumination_probe`、`learning_wordbook_entry` 与 `learning_review_record`）。
- 异步任务：状态可见、幂等领取、取消、异常恢复和失败项重试。
- 权限：普通用户数据隔离，管理员能力由权限注解统一控制。

## AI 响应验收

按 `AiInvocationScene` 对每类真实响应检查：

1. JSON 或文本是否可解析。
2. 必需字段、数量和类型是否正确。
3. 输入词、答案、选项和业务归属是否满足不变量。
4. 内容是否符合学习目标，是否存在机械堆词或不可靠反馈。
5. 问题属于 Prompt、供应商协议、解析器、场景编解码还是业务校验。

修复时保留脱敏失败样本，增加最小回归测试；不得通过放宽核心校验掩盖坏响应。真实响应正文只能在受控环境临时留存，完成后关闭，严禁保存密钥和未脱敏个人数据。

## 发布前检查

```bash
git diff --check
git status --short
```

同时确认数据库迁移顺序、前后端接口契约、移动端关键流程和无关文件未进入交付范围。
