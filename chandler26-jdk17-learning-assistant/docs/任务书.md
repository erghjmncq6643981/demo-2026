题目：基于大模型的英语学习助手

# （一）课题来源，意义与主要内容：（注明自拟、科研、科技服务类别及任务提出单位）
来源： 自拟

背景与意义：

2022 年底，OpenAI 发布 ChatGPT 3.5，引爆了全球对 AI 聊天机器人的追捧。随后国内各大厂商迅速跟进，相继推出通义千问（阿里）、豆包（字节）、DeepSeek（深度求索）、混元（腾讯）等大语言模型，AI 能力从“尝鲜”走向“实用”。然而，通用型 AI 聊天机器人虽然能回答各类问题，但在垂直学习场景中仍存在明显短板：生成内容不够精准、难以适配个人学习进度、无法有效沉淀和复习重点知识。

本人是一名具有十年工作经验的程序员，长期有英语学习需求，同时关注 AI 技术在产品中的应用。基于此，决定自拟课题，借助多模型 AI 能力构建一款个性化的英语学习助手，并以英语学习为切入点，后续可衍生至编程学习、专业文献阅读等更多场景。

核心意义在于：

通过“AI 生成 → 用户筛选 → 笔记管理 → 重复学习”的完整闭环，解决传统学习工具中“数据不精准、场景适配差、重点难提炼”三大痛点，覆盖查词、学习、复习、文章阅读等核心环节，最终显著提升用户的学习效率和知识留存率。

主要内容：

本课题将设计与实现一个基于多 AI 模型的英语词汇学习助手，主要包括以下五大模块：

1. AI Agent 模块：支持多供应商（DeepSeek、Kimi、豆包等）模型配置、Prompt 模板管理、会话与消息持久化，实现灵活可控的 AI 交互能力。
2. 词汇学习模块：输入单词或短语，调用 AI 生成结构化学习卡片（释义、音标、例句、搭配、记忆提示等），并通过归一化缓存避免重复调用，支持拼写容错和最佳匹配。
3. 文章学习模块：从单词本中选择词汇，结合字数范围、难度和备注，由 AI 生成包含英文文章、中文译文、词汇用法、语法点和练习题的完整学习材料，并支持历史记录复学。
4. 单词本及复习模块：支持多单词本管理、词条快照（防止公共缓存更新覆盖个人学习记录）、艾宾浩斯间隔重复复习（含睡眠时间保护）、字母跟敲练习、Markdown 笔记共享等。
5. 安全认证模块：基于 Spring Security + JWT 的用户注册登录、AES-GCM 加密存储模型 API Key、系统日志审计、用户偏好持久化等。

# （二）本课题研究的目的、要求和主要技术指标
目的：

开发一套基于多 AI 模型的个性化英语学习助手系统，实现从“查词学习 → 加入单词本 → 间隔复习 → 文章精读”的完整学习闭环，使学习者能够高效利用 AI 生成高质量学习内容，并通过科学的复习机制巩固记忆，同时保障数据安全和系统可扩展性。

要求：

1. 功能完整性：覆盖词汇学习、文章学习、单词本管理、复习计划、模型配置等核心功能，满足个人日常英语学习需求。
2. 多模型兼容性：支持接入 OpenAI-compatible 接口的多家 AI 供应商（DeepSeek、Kimi、豆包等），用户可在前端自由切换和配置模型。
3. 数据一致性：公共 AI 缓存与个人单词本快照分离，避免不同用户或多次生成相互覆盖；笔记在学习和复习页面实时同步。
4. 安全与隐私：模型 API Key 使用 AES-GCM 加密存储；用户密码使用带盐 SHA-256 哈希；JWT 无状态认证；系统日志持久化审计。
5. 用户体验：前端参考 qwerty-learner 风格，深色学习空间、卡片式焦点、字母跟敲练习、发音支持（有道词典回退浏览器 TTS）。
6. 可扩展性：保留 Agent、Prompt 模板、多场景（后续可扩展编程、数学等）的扩展能力，数据库设计支持后续迭代。

主要技术指标：

| 指标项 | 具体要求 |
| --- | --- |
| AI 模型支持数量 | ≥ 3 家供应商（DeepSeek、Kimi、豆包等），用户可自定义新增 |
| 词汇学习缓存命中率 | 同一归一化词条优先返回缓存，预期命中率 ≥ 95%（常用词汇） |
| 单次 AI 调用响应时间 | ≤ 10 秒（网络正常条件下） |
| 复习间隔算法 | 艾宾浩斯间隔：0、1、2、4、7、15、30、60 天，支持睡眠时间自动顺延 |
| 单词本容量 | 单个用户最多 50 个单词本，每个单词本最多 5000 个词条 |
| 用户并发支持 | 单节点 ≥ 100 并发用户（基于 Spring Boot + MySQL） |
| 系统日志保留周期 | ≥ 90 天，支持按类型和来源检索 |
| 前端页面加载时间 | 首屏 ≤ 2 秒（静态资源 CDN 或无缓存本地） |
| 拼写容错匹配精度 | 编辑距离 ≤ 2 的词汇可被正确推荐为最佳匹配 |
