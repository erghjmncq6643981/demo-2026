## 排查"AI 返回内容缺少必要字段：vocabulary"

- 现象：词汇大挑战场景单元生成（scene_unit）报 `AI 返回内容缺少必要字段：vocabulary`。
- 排查结论：**模型间歇性提前收尾**，非配置/提示词问题。
  - 提示词（ai_prompt_template 1201）明确要求 vocabulary 数组；失败调用 25.6s 结束，而成功调用 156s/189s（5945/6903 token）→ 失败那次输出量只有约 1/6。
  - 按真实请求体（模板+50候选词+`thinking:disabled`+`response_format:json_object`）直连复现成功：6 个根字段齐全、5897 token、18899 字符 → 非确定性。
  - vocabulary 是结构里最后一个字段，提前收尾或被 `completeClosingBrackets` 补括号后，缺的就是它。
  - 放大因素：`KimiChatRequestAdapter` 对 independentAction 场景固定下发 `thinking:{"type":"disabled"}`；该场景单次输出体量最大（50词×8字段 + 250-650词短文 + 逐段翻译），max_tokens=16000。
- 修复（本次）：
  - 新增错误码 `AI_RESPONSE_STRUCTURE_INCOMPLETE`，codec 缺字段时改抛此码（与"格式非法"区分）。
  - 新增 `AiStructuredResponseRetryPolicy`（`ai/chat/application`）：仅结构不完整时定点重试一次并追加纠正要求，次数由 `learning.ai.structured-response.max-attempts` 控制（默认2）。
  - `LearningPlanSceneContentService`、`LearningSceneRelatedVocabularyService` 接入该策略（改为注入 policy，不再直接注入 AiChatService）。
  - 提示词模板 1201/1204 加固（DB + `db/init/00_ai_agent_seed_mysql.sql` 双写）：四字段不可省略、vocabulary 必须完整、不得截断。
  - 单测：`AiStructuredResponseRetryPolicyTest`、`LearningPlanSceneContentServiceRetryTest` 通过。
- 排障工具：`scripts/repro_scene_unit.py`（读库解密 Key 后直连 Moonshot 复现该场景，不落盘不打印密钥）。
- 注意：`learning.ai.audit.store-content` 默认 false，失败响应原文不落库；需要看原文时临时设 true。
