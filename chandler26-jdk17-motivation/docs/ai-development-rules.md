# AI 开发规则

本文档是儿童激励记录系统的 AI 协作规则。后端、前端、数据库、设计文档都应遵守本文档。

## 项目边界

- 后端项目：`/Users/chandler/Documents/repository/github/demo-2026/chandler26-jdk17-motivation`
- 前端项目：`/Users/chandler/Documents/repository/github/demo-2026/chandler26-jdk17-motivation-web`
- 两个项目按一个前后端分离产品维护。
- 产品设计源文档放在后端项目 `docs/` 下。

## 后端规则

- 使用 Spring Boot、MyBatis-Plus、MySQL。
- 使用 Spring Security + JWT 做认证。
- Controller 保持薄层，业务逻辑放在 Service。
- API 入参和出参使用 DTO，不直接暴露数据库实体。
- 异常使用项目专属运行时异常，不直接抛通用 `RuntimeException`。
- 业务日志使用 info 级别，并尽量让非技术用户能读懂。
- 系统诊断日志使用 debug 级别。
- 重要操作写入 `motivation_system_log`。
- 积分余额只能由积分流水驱动，不允许跳过流水直接修改业务结果。

## 前端规则

- 前端项目与后端项目平级。
- 功能代码放在 `public/src/features/**`。
- 共享工具放在 `public/src/shared/**`。
- `public/app.js` 只做入口和轻量编排，不承载大量业务逻辑。
- 日历是核心视图，不是装饰模块。
- 儿童端页面要鲜明、直观、大按钮、强反馈。
- 家长端页面要清晰、可审核、可追踪。
- 破坏性操作、扣分、兑换撤销等动作必须二次确认。
- 修改布局后检查桌面和移动端。

## 数据库规则

- SQL 放在 `src/main/resources/db/init`。
- 新库初始化脚本按编号执行。
- 如果用户已执行旧 SQL，后续结构变化新增补丁 SQL，不悄悄改已执行意图。
- 表和字段必须有清晰中文注释。
- 用户、孩子、任务、积分流水、奖励兑换等高频查询需要索引。
- 所有积分变动写入 `motivation_point_ledger`。
- 奖励兑换要能追踪到扣减积分流水。

## 产品规则

- 一个孩子可以有多个目标。
- 一个目标可以有每日、每周、每月任务。
- 每个任务可以独立设置任务颜色、积分类型、积分颜色和基础分值。
- 星星、红花、皇冠是积分类型，不是简单图标文本。
- 任务完成、手动加分、手动扣分、奖励兑换都要可追溯。
- 扣分必须有原因。
- 默认不让孩子积分余额变成负数。
- 奖励兑换可以配置是否需要家长确认。

## AI 功能规则

- AI 可以生成任务建议、奖励建议和家庭激励方案。
- AI 生成内容必须先进入草稿或建议状态，不能自动生效。
- 家长确认后，AI 建议才可以变成正式任务、规则或奖励。
- AI 生成的规则需要结构化保存，便于前端编辑和后端验证。

## 验证要求

- Java 修改后至少运行 `mvn -q -DskipTests compile`。
- JS 修改后至少运行 `node --check`。
- UI 或交互修改后使用浏览器验证。
- SQL 修改后检查语法、注释、索引和实体字段一致性。
