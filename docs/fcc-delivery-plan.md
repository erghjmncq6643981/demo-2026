# FCC 交付计划

## 1. 使用方式

本文是 FCC 优先级、依赖、状态和完成条件的唯一来源。产品现状见 [产品设计](fcc-product-design.md)，技术细节见 [Java 控制面设计](../chandler26-jdk21-fcc/docs/DESIGN.md) 与 [Sidecar 设计](../../cloud-2025/chandler25-fs-sidecar-agent/docs/DESIGN.md)。

状态含义：

- **已实现，待联调**：源码和必要静态/自动化检查具备，但没有真实 FreeSWITCH/SIP/媒体证据。
- **进行中**：只有部分闭环，不能作为可交付能力使用。
- **待实施**：设计方向明确，尚无完整运行实现。
- **暂缓**：不进入首个可用版本。

## 2. P0：首个可用版本

| 顺序 | 交付包 | 当前状态 | 完成条件 |
| --- | --- | --- | --- |
| 1 | 身份、权限与终端 | 已实现，待联调 | 话务 REST/WS 只接受认证主体；本人 SIP 配置不可缓存和泄漏；越权控制、客户读取、录音和终端切换被拒绝；`0000` 并发换绑唯一 |
| 2 | 命令、事件与恢复 | 进行中 | 重复命令不重复拨号；稳定事件去重且终态不回退；NATS/Java/Sidecar 重启后能恢复或明确进入待对账状态；未知副作用不盲重试 |
| 3 | 呼入与两类人工外呼 | 已实现，待联调 | DID 命中固定流程；系统先呼坐席和终端主动拨号两条链路均完成双向音频、桥接、挂机、CDR；离线注册投影不提前阻断 Dial |
| 4 | 流程发布与运行固定 | 已实现，待联调 | 同一流程最多一个发布版本；草稿发布事务失败时旧版本仍有效；新通话固定版本；刷新失败保留旧快照；激活状态可核对 |
| 5 | 录音、评价与媒体 | 进行中 | TTS 文案经 Sidecar 生成并播放；录音开始、停止、文件完成态和授权读取一致；评价、结束语音及异常出口有事实记录 |
| 6 | 客户资料与 Windows 弹屏 | 已实现，待联调 | 客户匹配失败不阻断通话；弹屏不重复、不过期、不越权；前台/最小化/托盘/锁屏/断网场景均有明确回执；安装包交付边界清楚 |

P0 发布门槛：构建和契约测试通过，真实呼入/呼出与双向媒体通过，权限否定用例通过，断网/重启恢复通过，CDR/Leg/命令/事件/录音可按同一通话核对。任何一项仅有 Mock 或同步 `ACCEPTED` 都不能视为通过。

## 3. P1：完整业务闭环

| 顺序 | 交付包 | 当前状态 | 完成条件 |
| --- | --- | --- | --- |
| 1 | ACD、排队与 ACW | 进行中 | 并发分配不会占用同一独占坐席；排队超时、无人、溢出和坐席释放有明确结果；小结提交/超时释放可追溯 |
| 2 | 回拨工作流 | 进行中 | 原 Call 关联、原子领取、预约、重试退避和终态完整；重复点击不创建重复任务，成功项不重拨 |
| 3 | 自动外呼 | 进行中 | 通知型和渐进式完成真实话务；多实例不重复领取；暂停/取消语义明确；时段、频控、未知结果对账和逐项重试有效 |
| 4 | 成熟 IVR 业务细节 | 进行中 | 营业时间、顺振/代班、排队溢出、异常出口和第三方业务回调显式动作化，不再隐藏在事件监听器分支中 |
| 5 | 转接与班长能力 | 待实施 | 盲转、咨询转、咨询失败恢复和三方通话闭环；监听、耳语、强插、强拆具备权限、媒体方向和审计证据 |
| 6 | 录音生命周期与运营统计 | 进行中 | 就绪/失败/缺失可区分，下载有审计和保留策略；接通、放弃、排队、通话、整理时长可从事实重算 |
| 7 | 多节点与运行运维 | 待实施 | Coordinator 维护 ownership、容量和 context 可用性；排水、聚合快照、跨节点控制、存储告警和版本激活失败可恢复 |

自动外呼是 `fcc-server` 的核心能力，排在基础通信之后是依赖顺序，不代表它是可选扩展。客户和自动外呼的界面位于管理端，坐席端只消费被分配的通话、回拨和弹屏。

## 4. P2：需求驱动扩展

- `MOBILE` 真实接听与运营商线路策略。
- 外部 CRM/工单成品适配器。
- 可插拔自定义阶段、复杂循环和更丰富的可视化编排。
- 预测式外呼、AI 质检、检索和高级报表。

P2 只有在 P0/P1 运行指标稳定且存在真实业务需求时启动。

## 5. 跨包约束

- `fcc-admin` 维护/查看，`fcc-server` 使用/执行；Sidecar 不承载客户、坐席和调度规则。
- Java 不选择 `nodeId`，不拼接 FreeSWITCH gateway/profile 拨号串；命令只表达号码、`routingContext`、媒体和幂等信息。
- 调度任务和长耗时工作先持久化再执行；失败项单独重试，不重复处理成功项。
- 事件、流程发布、录音和弹屏均必须区分“受理”“最终事实”“用户或媒体实际可见”。
- 协议变更同步更新 Java/Go fixture，先部署兼容的 Sidecar，再部署 server，最后更新前端。
- 当前只支持空库基线。进入生产变更管理后，Schema 变化必须附不可变迁移、执行顺序、冲突检查和回退方案。

## 6. 每次交付记录

交付说明只记录本次实际执行结果，至少包含：

1. 变更范围及受影响工程；
2. 已执行且通过的命令；
3. 已执行但失败的首个有效错误；
4. 因缺少依赖而未执行的检查；
5. 真实 FreeSWITCH、SIP、媒体、浏览器和 Windows 验收范围；
6. 遗留风险及下一步。

一次性测试数量、机器版本和临时环境故障不写入长期架构文档。
