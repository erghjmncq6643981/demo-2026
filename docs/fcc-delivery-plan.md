# FCC 分阶段实施与验收

决策日期：2026-09-19。本文是待办、依赖和执行状态记录，不是已交付能力说明。现状见 [产品设计](fcc-product-design.md) 与 [控制面设计](../chandler26-jdk21-fcc/docs/DESIGN.md)。全新 FreeSWITCH 项目，不引入旧业务协议兼容层。

## 1. 职责决定

- fcc-server：话机绑定运行流程、呼入、呼出、自动外呼调度、客户资料、Windows 弹屏业务及持久事实。
- Sidecar：ESL、结构化话务原语、事件标准化、注册/通道查询、节点治理与恢复；不承载上述业务规则。
- fcc-admin：基础资料、权限与管理入口；旧工号 IVR 绑定接口与实现已移除，运行绑定归 fcc-server。
- Windows 客户端：执行服务端弹屏指令及本机交互，回传结果；不自行决定客户归属或调度外呼。

先采用 Electron 复用 Vue，接受安装体积成本以减少首版技术栈和 WebRTC 环境差异。首版以实体话机通话，桌面软件承载业务；桌面 WebRTC 后续验收。Windows 焦点限制、锁屏和专注助手下不得承诺强制抢焦点。

## 3. 每包实现约束

### 通信可靠性

结构化保持/恢复/DTMF逐步替代业务层 NativeAPI 拼接。命令记录 commandId、nodeId、业务幂等键及受理/失败/未知/完成，超时先查询不盲重拨。事件包含稳定 eventId、节点启动标识和源时间；Java 在状态更新前去重，终态不可被迟到振铃覆盖。

持久事件采用 JetStream，部署前必须确认 stream/subject、保留、ACK、重投和死信处理。Java Inbox 在处理前去重：明确失败会 NAK 并最多重新领取 5 次，已完成的重复事件直接 ACK；服务中断时遗留的 `PROCESSING` 和耗尽重试的 `FAILED` 转为 `UNKNOWN`，交由人工或对账任务处理。Sidecar 发布失败也要补偿；仅消息系统持久化不能补回从未发布的事件。业务副作用与 Inbox 状态仍不在同一事务，真实 JetStream 重投行为尚未在本机验证。

恢复同时依赖通道/桥接/注册快照，快照失败不等于所有通话结束。当前 Sidecar 已实现 UUID 容量计数及内部周期快照；已通过 FNode.ChannelSnapshot 向 Java 提供只读查询。成功快照中双方持续缺失 120 秒才结束并释放占用，失败快照重置缺失计时；桥接重建和单边残留对账尚未实现。

### 话机绑定

先检查 API、DTO、服务、三处绑定数据、索引和 0000 入口，再统一写入责任。分机身份来自 Sidecar 上报的已认证 SIP 分机；工号用于选择绑定坐席，不代替分机身份认证。使用唯一约束与事务锁定策略，并同步失效旧 endpoint binding。新项目不保留匿名或旧流程兼容入口。

### 客户资料及 Windows 弹屏

客户主数据与查询授权属于 fcc-server。号码规范化后关联客户；同号多客户不得任意选取。来电事件仅含必要摘要及不透明 ID，大资料通过授权详情接口加载，客户查询失败不阻断通话。

服务端决定弹屏收件人、脱敏内容、生命周期、补发与过期规则。客户端按事件/通话身份去重，区分收到、展示、用户操作；展示回执不代表接听成功。单一业务连接通过受限 IPC 分发事件，禁止开放任意本机命令或本地无认证控制 HTTP。测试签名安装、更新失败恢复、托盘退出、断网与重新登录；Windows 原生限制作为明确可观测结果。

### 自动外呼

通知型：拨号→应答→播放→收号→结果。渐进式：预占坐席→坐席就绪→拨客户→桥接→整理。共享统一呼出服务；任务先持久化再执行，领取有租约和恢复机制，每次尝试单独记录。支持呼叫时段、号码频控、最大次数、退避、忙线/未应答/网关失败分类；取消与暂停明确处理已开始的尝试，不直接等同强制挂机。

## 4. 验证与上线

2026-09-20 本轮证据：JDK 21 编译通过；Flow 定义、系统模型、动作执行器、事件 Inbox 与发布/重载边界共 20 项定向测试通过；管理端构建及 4 项治理测试通过；本轮修改的 Mapper XML 已完成静态解析。完整 `mvn test` 在首个外部依赖 NATS 处失败：fcc-server 共运行 35 项，9 项 Spring 上下文错误、1 项跳过、0 项断言失败，不能记为全量通过。仓库当前没有 FCC 增量迁移脚本，本轮没有连接 MySQL、NATS/JetStream、Redis、Sidecar、FreeSWITCH、SIP 或 Windows 环境，也没有完成认证浏览器回归。

每包更新实际状态和验证证据；源码完成、自动测试通过、真实环境验收分别记录。Java 执行编译及全量测试；Go 执行生产包测试及构建；前端执行类型/构建和交互验证。协议变更需 Java/Go fixtures 同步，先部署具备所需能力的 Sidecar，再发布依赖该能力的 server，最后更新客户端；不支持的能力明确拒绝。

当前全新项目只支持使用 `chandler26-jdk21-fcc/docs/fcc-schema.sql` 初始化空库，不支持旧库升级。进入生产变更管理后，Schema 变更必须新增不可变迁移、执行顺序、数据冲突检查与修复策略，并先在一次性 MySQL 8 数据库验证，不能以静态 SQL 审查替代。真实联调还需 Redis、NATS/JetStream、PostgreSQL、FreeSWITCH、SIP 话机及 Windows 桌面环境。

持续指标：漏接率、来电到弹屏时延、重复拨号次数、故障恢复耗时、单通定位耗时。先建立基线再设目标，不虚构已经达到的 SLA。诊断时间线贯穿 callId、channelUuid、commandId、eventId、nodeId，电话和客户资料按权限脱敏。
